## Current status

The rebuild provides the original offline GUI flow through `DRIVERS\\GXSOFT.DLL`: the six-logo introduction leads to the five-row main menu, game-type selection, character selection, and map selection. Keyboard navigation, row dispatch, quit confirmation, clean shutdown, menu sound effects, the animated, textured, lit 3D character preview, and the five-entry map carousel are functional.

The character-selection scene uses the original `SEN`/`TPG` asset pipeline and scene-graph, animation, projection, material, and polygon-rendering paths. All ten character models can be selected and previewed; pressing Enter enters `stateLevelSelect`, where locked/unlocked map previews, five-pixel `sinf` arrow wobble, arrow navigation, Escape return, and the original five level-entry contracts are implemented.

The first gameplay level now loads and renders: selecting a map parses `run <level>`, and `roundStartInit @0x40a4d0` executes its original two-pass structure — GX re-init with the real window/hInstance pair, pool system init, first `scenNameTableInit(10000,10000)`, the `levelSceneTexturesLoad @0x4104b0` texture/`ph`-scene pre-pass (merged per-level `TPG` textures, aqua/orient/future extras, `FLOOR` nav-node collection, zone wall list), the `load.tga` flash, the second `scenNameTableInit(4000,4000)` pass, `configMasterLoad`, and `levelSetup @0x4108a0`, which loads the level mall/objects/character scenes plus the texture-scene pre-load with working mesh-name resolution (`scenNameToId @0x431ed0`); all 30 configured item slots resolve their meshes. The configuration subsystem (XOR-0x55 `maniac.cfg` → `sommar.sol` parsing, `levels[]`/`items[]` grammar) is implemented.

The gameplay frame renders the mall (scene-graph OBJI instantiation in `sceneLoadSen @0x432320`, the exact per-node cull of `sceneNodeRender @0x42f8c0` with the raw-int renderT semantics of `sceneRender @0x42f1c0`), the local player character with cart and an AI player rolled by `playerSetupCharacters @0x41b6e0` (player count from the `g_kModePlayerCounts @0x44b610` table, unique random AI characters, local/AI cart and control assignments), placed by the `levelObjectsCartsCameraInit @0x411b70` per-player pass (cart/character turret+mesh collision clusters via `objTurretAdd @0x405280`/`nodeAddChildMesh @0x4053a0`/`objTurretSetValue @0x405370`, `handle_pos` cart children, `start_positions` placement through `nodeSetTransformFromChannels @0x404e00` with the `sceneRayFindNearest @0x42a750`/`zoneWallCircleHit @0x42aac0`/`zoneWallPointSide @0x42a870`/`mathSegIntersect @0x406130` floor-raycast chain) and followed by the config-driven gameplay camera. The HUD overlay (`renderGameHud @0x412810`) draws over every frame: shopping-list panel with the sliding reveal bar and real item names (`g_apLevelItemSlots @0x4583c8`, placed item objects via the roundStartInit event-object pass), `Varor` counter, race timer, checkout banner and progress bar, character face, rank counter, results screen with winner face and toplevel/high-score commands, quit prompt, and the `Klara!/Färdiga!/Gå!!` countdown with sfx; its four textures load through `hudLoadGraphics @0x412700` and the three per-level HUD fonts (`g_hHudFont @0x458364`, `g_hHudFontDigits @0x458368`, `g_hHudFontTiny @0x45836c`) load in `roundStartInit @0x40a727..0x40a7f7`. The frog-question bank loads via `questLoad @0x40ffa0` (430 records). The round clock is live: `roundLogicUpdate @0x40beb0` runs per world tick and drives `g_nGamePhase @0x458124` (limit 7000 ms from `levelDirectorInits @0x40bdf0` over the config `obj_update_time` step — 175 ticks of 40 ms), latches −20 on overtime (the HUD flashes `Gå!!` and counts back to 0), increments every player's `nScoreTicks` in overtime, and the mode win checks (list progress + `goal` checkout zone → `KUNDKORT` card, sfx, results screen) plus the mode-3 item spawner are in place; the level event directors `levelEventDirector_L0..L4` remain documented no-op stubs. ## Scope and build

The target is `/home/wasd/MallManiacsUnmodified/maniac_rebuild.exe`, built for 32-bit Windows with `i686-w64-mingw32-gcc` and the required `KERNEL32`, `USER32`, `GDI32`, and `WINMM` libraries. Rendering uses the original software rasterizer through `GXSOFT.DLL`; a GDI backend is not used.

The implementation covers the offline GUI and the available single-player character-selection path while preserving the original call hierarchy. Reimplemented functions and globals retain original-address comments in source. Detailed reverse-engineering notes belong in subsystem documentation.
